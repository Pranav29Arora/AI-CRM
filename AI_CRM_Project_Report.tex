% --- Abstract ---
\begin{abstract}
Small and medium retail and wholesale distributors routinely negotiate commercial transactions over unstructured instant messaging channels like WhatsApp. This practice causes severe margin leakage, slow quote turnaround, and lead churn. This paper presents \textbf{AI-CRM}, a cloud-native platform integrating reactive client interfaces, deterministic financial guardrails, and Large Language Model (LLM) intelligence via Google Gemini. The platform introduces a \emph{zero-hallucination constraint model} that completely isolates natural language generation from pricing boundaries: while generative AI synthesizes persuasive B2B counter-offers, immutable server-side mathematical rules prevent quotes from falling below strict profitability floors. We evaluate the reactive client (React 18/Vite), cryptographic session orchestration (Firebase Auth/Cloud Firestore), background reminder workers, and pricing verification suites, demonstrating resilient offline recovery and deterministic sub-100ms pricing validation.
\end{abstract}

\begin{IEEEkeywords}
CRM, Automated Negotiation, Zero-Hallucination, Firebase Auth, Google Gemini, Cloud Firestore.
\end{IEEEkeywords}

\section{Introduction}
\label{sec:intro}

\IEEEPARstart{W}{holesale} distributors and merchants operate in high-turnover, low-margin sectors where quote latency and price negotiation dictate profitability. Modern distributed supply chains frequently conduct B2B negotiations across informal messaging tools (e.g., WhatsApp). This causes three operational failures:
\begin{enumerate}
    \item \emph{Margin Erosion:} Under conversational pressure, sales representatives concede arbitrary discounts breaching volume cost curves, creating sub-floor, profit-negative deals.
    \item \emph{Quote Attrition:} Inquiries received outside operating hours are neglected without automated follow-up mechanisms, resulting in buyer churn to competitors.
    \item \emph{Suboptimal Tactics:} Frontline staff often lack tactical negotiation alternatives (e.g., warranty bundling or stepped pricing) when an initial offer is rejected.
\end{enumerate}

To resolve these hurdles, we engineered \textbf{AI-CRM}. Its core contribution is the strict decoupling of conversational fluency from transactional authorization: generative AI acts as a communication copilot, while a deterministic backend engine enforces non-negotiable profit boundaries.

\subsection{Presentation Tier (React 18 + Vite)}
The user interface is an SPA built with React 18 and bundled via Vite 6.4. Styling uses TailwindCSS utility tokens with mobile-first responsiveness. State is governed by a global \texttt{AuthContext} providing reactive session persistence and route protection.

\subsection{Application Tier (Node.js/Express)}
The backend executes transaction validation, mathematical pricing boundary checks, and background cron workers for reminder dispatching.

\subsection{Cloud Services Tier (Firebase \& Gemini)}
Identity management and NoSQL document persistence are handled by Google Firebase (\texttt{ai-crm-f73a5}). Generative strategy recommendations are synthesized via Google Gemini (\texttt{gemini-3.5-flash}).

% SECTION III: MATHEMATICAL PRICING MODEL
% ==============================================================================
\section{Deterministic Pricing Safeguard Model}
\label{sec:pricing}

To eliminate generative hallucination risks in financial quotes, pricing logic is isolated from LLM prompt outputs.

\subsection{Parameter Formalization}
Each inventory item $i$ is defined by the quadruple:
\begin{equation}
    P_i = (C_i, F_i, M_i, T_i)
\end{equation}
where $C_i$ is unit cost, $F_i$ is the absolute floor price ($F_i > C_i$), $M_i$ is preferred minimum price, and $T_i$ is target price ($T_i \ge M_i > F_i$).

For buyer offer $P_{\text{offer}}$ and volume $Q \in \mathbb{N}^+$, gross profit $G$ and gross margin percentage $\mu$ are computed as:
\begin{align}
    G(P_{\text{offer}}, Q) &= (P_{\text{offer}} - C_i) \cdot Q \\
    \mu(P_{\text{offer}}) &= \left(\frac{P_{\text{offer}} - C_i}{P_{\text{offer}}}\right) \times 100\%, \quad P_{\text{offer}} > 0
\end{align}

\subsection{Decision Function and Concession Formulation}
The evaluation engine executes an immutable state machine $A(P_{\text{offer}}) \in \{\text{REJECT}, \text{COUNTER}, \text{ACCEPT}\}$:
\begin{equation}
    A(P_{\text{offer}}) = 
    \begin{cases}
        \text{REJECT}, & \text{if } P_{\text{offer}} < F_i \\
        \text{COUNTER}, & \text{if } F_i \le P_{\text{offer}} < M_i \\
        \text{ACCEPT}, & \text{if } P_{\text{offer}} \ge M_i
    \end{cases}
\end{equation}

When $A(P_{\text{offer}}) = \text{COUNTER}$, the recommended counter $P_{\text{counter}}$ converges towards $M_i$ bounded strictly by floor $F_i$:
\begin{equation}
    P_{\text{counter}} = \max\left(F_i, \; \left\lfloor \frac{P_{\text{offer}} + 2 M_i}{300} \right\rceil \times 100\right)
\end{equation}
This bounds concessions while rounding to clean B2B currency units.

\section{System Implementation}
\label{sec:impl}

\subsection{Firebase Identity Management \& Session Lifecycle}
Authentication uses the Firebase Auth SDK v10. \texttt{AuthContext.jsx} subscribes to \texttt{onAuthStateChanged}, maintaining token state and preventing race conditions during page reloads. Outgoing API requests pass through a bearer interceptor in \texttt{api.js} that auto-refreshes expired tokens on HTTP 401 and replays queries seamlessly.

\subsection{Defensive Error Mapping \& Route Guards}
Raw database exceptions are intercepted and mapped to user-friendly notifications (e.g., mapping \texttt{auth/invalid-credential} to an anti-enumeration alert). Declarative route wrappers (\texttt{ProtectedRoute} and \texttt{PublicOnlyRoute}) prevent unauthorized dashboard access while preserving redirect destinations via \texttt{location.state.from}.

\subsection{AI Deal Intelligence Engine}
The negotiation copilot in \texttt{ai.service.js} interfaces with Google Gemini. It incorporates dynamic model discovery: initializing on \texttt{gemini-3.5-flash} (\texttt{v1beta}), with failover to \texttt{gemini-flash-lite-latest}. Prompts inject computed values of $F_i$ and $P_{\text{counter}}$, instructing the LLM to generate structured JSON containing persuasive WhatsApp-ready messages without violating margin limits.

\subsection{Automated Follow-Up Worker \& Data Schema}
A background worker (\texttt{reminder.worker.js}) scans Cloud Firestore on an automated heartbeat. Quotes pending $> 48$ hours trigger follow-up alerts. Data is organized across three Firestore collections: \texttt{users} (profiles and roles), \texttt{products} (cost, pricing ladders, inventory), and \texttt{enquiries} (buyer bids, deal status, transcripts).

\section{Conclusion and Roadmap}
\label{sec:conclusion}

\textbf{AI-CRM} resolves margin leakage and quote delays in commercial distribution by unifying responsive web interfaces, cryptographic Firebase identity verification, real-time Cloud Firestore synchronization, and zero-hallucination AI negotiation guardrails. Future phases will integrate the Meta WhatsApp Business Cloud API for direct bidirectional messaging and vector embeddings for customer deal history retrieval.
